# 智能旅行助手

一个本地运行的网页应用：输入所在城市、目的地城市、出发日期和旅行天数，自动生成一份完整旅行方案，包括火车票推荐、酒店推荐、天气预报和每日游玩路线。

## 功能

- **自然语言需求**：可选填「个人需求」，如出发时间、上车站点、酒店价格区间、景点偏好等
- **多份具体方案**：根据需求生成 2-3 份完整方案（车次 + 酒店 + 门票 + 路线 + 总花销），供直接挑选
- **反馈修改**：对方案不满意可输入反馈，助手据此迭代调整方案
- **直达 vs 中转对比**：可选填中转城市，生成含中转的省钱方案
- **天气预报**：目的地未来几天天气（免费 wttr.in），按行程日期对齐
- **景点门票**：查询各景点真实门票价格（途牛）
- **花费汇总**：每份方案都给出往返车票 + 酒店 + 门票的总价（**由代码重算，非模型估算**）
- **输入校验**：城市名无效会立即提示；输入省份则列出该省主要城市供选择

## 数据源

| 用途 | 来源 | 密钥 |
|------|------|------|
| 火车票 / 酒店 / 门票 | 途牛开放平台 MCP | `TUNIU_API_KEY` |
| 天气 | wttr.in（免费） | 无 |
| 景点资讯 | Tavily | `TAVILY_API_KEY` |
| 规划与结构化输出 | DeepSeek | `DEEPSEEK_API_KEY` |

## 架构：ReAct（Reasoning + Action）

规划层采用 ReAct 范式：把车次、酒店、门票、天气、景点搜索包装成 5 个「工具」，
通过 DeepSeek 的 function calling 能力，让模型自主决定查什么、按什么顺序查，
跑「思考 → 行动 → 观察 → 再思考」的循环，直到信息足够后输出最终方案。

## 快速开始

### 1. 安装依赖

需要 Python **3.11+**（总时长预算使用了 `asyncio.timeout`）。

```bash
python -m pip install -r requirements.txt
```

### 2. 配置密钥

复制 `.env.example` 为 `.env`，填入三个密钥：

```bash
TUNIU_API_KEY=你的途牛key
DEEPSEEK_API_KEY=你的deepseek key
TAVILY_API_KEY=你的tavily key
```

### 3. 启动

```bash
python run.py
```

浏览器打开 <http://127.0.0.1:8000> 即可使用。

## 说明与已知限制

- **只做推荐，不真正下单**：火车票和酒店仅查询对比，不发起预订。
- **天气只在出发日临近时才有**：免费源 wttr.in 只提供**从今天起** 3 天预报。出发日超出这个范围时，
  页面会明确提示「暂无可用天气数据」，而**不会**把今天的天气当成出发日的天气展示。
  行程中落在预报范围内的天数会正常展示，不足的部分在「请注意」区说明原因。
- **酒店价格是起价**：途牛返回的 `lowestPrice` 是最低房型的单晚起步价（可能是无早/不可取消房型），
  不是成交价，方案里会注明「以预订页为准」。
- **酒店住 N-1 晚**：旅行天数 N 天按「玩 N 天、住 N-1 晚」理解（入住=出发日，离店=出发日+N-1）。
  1 天行程为当天往返，**不安排住宿**，总价不含酒店费用。
- **往返车票**：去程 = 出发日，回程 = 出发日 + 天数 - 1（最后一天返程）。
- **单次规划有时长上限**：整轮 ReAct 循环默认限制 180 秒，超时返回 504 并提示重试。
- **途牛接口**：采用无状态 JSON-RPC，直接 HTTP 调用，后端不依赖 Node。
- **只支持国内城市**：城市校验使用内置的中国城市表。表外的中文地名会放行给数据源判断，
  查不到结果时会提示；非中文输入（乱码）会被直接拦截。
- **市内游**：出发地与目的地相同时按「市内游」处理——不查城际车次、不计交通费用，
  并在页面明确提示。若这不是你的本意，请修改出发地或目的地。
- **输入关系校验**：中转城市不能等于出发地或目的地；出发日期不能早于今天。
- **总价由代码重算**：模型负责编排方案，但 `total_cost` 由后端按
  「去程 + 回程 + 酒店 + 门票」重新计算。若与模型给出的一致则不动，不一致则修正并在页面提示。
- **行程会做一致性校验**：天数是否与要求一致、日程序号是否连续、回程是否早于去程
  （时间倒挂）、日程日期是否越界——发现问题会在「请注意」区列出。

## 测试

```bash
# 零依赖自检（不需要装 pytest）
.venv/Scripts/python.exe tests/selfcheck.py

# 完整单测
python -m pip install -r requirements-dev.txt
.venv/Scripts/python.exe -m pytest tests/ -v
```

测试覆盖三处「用代码替代模型做判断」的纯函数：城市校验、总价重算、行程时间线校验，
以及 `days=1` 的日期边界不变式。

## 观察 Agent：执行轨迹

页面底部有一个折叠面板「🔍 Agent 执行轨迹」，展示每次规划的真实执行过程：
每轮 LLM 调用的 token 用量、每个工具的耗时与失败情况、模型的调用顺序与参数。

**这不是调试功能，而是理解 agent 的窗口。**

读代码只能知道「可能的路径」，只有轨迹能告诉你「实际走了哪条」——
模型按什么顺序查数据、跑了几轮、prompt_tokens 涨到多少、哪个工具在失败。

如果你是抱着**学习 agent** 的目的看这个项目，请从
**[docs/用轨迹学习Agent.md](docs/用轨迹学习Agent.md)** 开始——
里面讲了每个数字该问什么问题，以及四个可以立刻做的实验。
